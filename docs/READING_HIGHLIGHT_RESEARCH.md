# 原页高亮：阅读效率与 AI 介入研究

## 产品问题

目标不是单纯缩短阅读时间，而是在理解不下降的前提下，让用户更快完成当前阅读任务。产品指标应优先使用“正确答案 / 分钟”或“达到理解门槛所需时间”，而不是孤立的每分钟字数。

## 现有证据

1. **高亮本身不保证更好的理解。** 一项数字阅读随机实验比较了用户主动高亮、研究者预先高亮和无高亮，整体上没有发现条件主效应；高亮质量与部分理解和迁移结果相关，读者个体差异也会调节效果。意义：选得对比“有没有高亮”重要，而且一种默认方案不一定适合所有人。
   来源：[Mason et al., 2024](https://doi.org/10.1111/jcal.12903)

2. **Bionic Reading 式词首加粗没有可靠的眼动收益。** 眼动研究没有发现显著的阅读速度、注视次数或注视时长变化，读者也没有只看词首就自动补全低频词。意义：不能把固定词首或固定字符位置当成科学成立的速读机制。
   来源：[Guiding the Gaze, 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC12565662/)

3. **中文阅读需要同时考虑词和字符，固定落点模型过于简单。** 中文眼跳既受词属性影响，也可能采用字符、词和当前加工难度共同决定的策略；研究不支持一个稳定、普适的词内最佳落点。意义：完整词边界值得保护，但不能声称某个固定位置就是人的下一次注视点。
   来源：[Li, Liu, & Rayner, 2011](https://pmc.ncbi.nlm.nih.gov/articles/PMC3119713/)、[Wei, Li, & Pollatsek, 2013](https://pubmed.ncbi.nlm.nih.gov/23231957/)

4. **正确标出中文词边界可能帮助眼动，错误边界会产生干扰。** 交替颜色与真实词边界一致时，部分中文读者群体的眼动指标得到改善；错误分组则会干扰阅读。意义：宁可少标，也不能拆词或制造错误词组。
   来源：[Zhou et al., 2018](https://doi.org/10.3758/s13421-018-0797-5)、[后续年轻与老年读者实验](https://pmc.ncbi.nlm.nih.gov/articles/PMC12000219/)

5. **“保留语法骨架、弱化细节”比普通逐词视觉技巧更有希望。** GP-TSM 使用递归句子压缩识别核心意义和细节层级，在一个小型实验中（n=18）得到更高偏好，并让参与者更高效地回答 GRE 阅读理解问题。样本很小，但它直接支持“语义骨架”方向。
   来源：[Gu et al., 2024](https://arxiv.org/abs/2401.10873)

6. **关键短语提取技术成熟，但“像人工关键词”不等于“提高阅读效率”。** 预训练语言模型可以做关键词抽取、排序和生成，常见目标是概括文档主题、加速信息检索；现有评估主要衡量与人工关键词的一致性，而不是人的阅读速度或理解。
   来源：[Keyphrase Extraction Survey, EACL 2023](https://aclanthology.org/2023.findings-eacl.161/)

7. **大模型零样本抽取有潜力但不稳定。** 同一研究团队的实验发现，ChatGPT 在关键词生成上有潜力，但作为严格的零样本关键词抽取器仍落后于专门的监督或无监督方法。意义：大模型适合作为候选排序器和研究助手，不应直接掌管字符偏移。
   来源：[LLMs as Zero-Shot Keyphrase Extractors, 2023](https://arxiv.org/abs/2312.15156)、[ChatGPT as Keyphrase Generator, 2023](https://arxiv.org/abs/2303.13001)

## “有说法”的高亮对象

默认模式不应只高亮主题名词，而应优先组成一条可读的语义骨架：

- 主题实体与核心概念；
- 主要动作或判断；
- 因果、转折、条件与结论；
- 数字、比例、时间和证据；
- 否定、范围和不确定性限定词；
- 当前段落中新出现或被反复承接的概念。

同时降低以下内容的优先级：

- “之前、之后、部分、内容、目前、这里”等脱离上下文后信息量很低的泛词；
- 已经由原网页用粗体、链接、颜色或 `mark` 强调的文字；
- 导航、按钮、代码、页脚和推荐内容；
- 只因位置接近目标间距而被选中的词。

## AI 最合适的介入方式

AI 不直接返回字符位置，也不直接修改页面。建议使用“本地候选 + AI 排序 + 本地约束”的三层结构：

```text
浏览器本地分词与候选词
  → AI 为候选 ID 标注语义角色与重要性
  → 本地选择器执行密度、间距、词边界、既有强调避让
  → 本地 DOM 渲染
```

模型输入只包含段落文本和本地候选 ID；模型输出只能包含：

```json
{
  "candidates": [
    { "id": "c7", "role": "claim", "score": 0.91 },
    { "id": "c12", "role": "evidence", "score": 0.83 }
  ]
}
```

允许的角色首版限定为：`topic`、`claim`、`action`、`cause`、`contrast`、`evidence`、`negation`、`qualifier`。

这种边界保证：

- 模型不能切断中文词语；
- 模型不能制造不存在的文字；
- 模型失败时立即回退本地引擎；
- 视觉密度和页面安全仍是确定性的；
- 后续可以把模型判断蒸馏成离线小模型或规则。

## AI 晋级实验

在 AI 回到用户运行时之前，必须做三条件、同一批读者内的随机对照：

1. 原文无高亮；
2. 当前本地启发式高亮；
3. AI 语义骨架排序 + 同一套本地渲染。

材料使用至少 12 篇此前未参与开发的中文文章，覆盖新闻、评论、技术说明和访谈。每篇设置事实查找题、推理理解题和延迟回忆题。

建议的产品晋级门槛（是预先承诺，不是研究事实）：

- AI 条件相对本地条件的任务完成时间中位数改善至少 10%；
- 即时理解正确率下降不超过 3 个百分点；
- 延迟回忆不低于本地条件；
- 主观负荷不增加，且没有更多“被错误重点误导”的报告；
- 远程排序不阻塞首屏，本地高亮先在 300ms 内出现；
- 用户未主动授权时不发送正文，正文与模型输出默认不持久化。

任一门槛不满足，AI 继续只用于离线标注、失败分析和规则迭代，不进入默认产品路径。

## 当前决定

- P0 继续使用完全本地、确定性的高亮引擎。
- 立即把选词目标从“定距内容词”升级为“语义骨架的本地近似”。
- AI 作为独立实验条件开发，不替换本地基线。
- 产品主指标从“高亮数量 / 位置重合率”改为“理解约束下的阅读任务效率”。
