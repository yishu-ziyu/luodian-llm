## 关键决策

1. **保留 A-side 修复**：skip thinking block + 二分重试。比 round-7 多了一层防御，但 B-side 没解决前还是会有 50% 失败。
2. **Rule 3 双语分支**：「first content word」措辞同时落到 ZH / EN few-shot 的 prompt。Austen en-3 first anchor 改 [8,2]="is" → [14,2]="tr"，Pangram en-1 保留 [0,2]="Th" 作为"段首短文"教学例外（理由详细写在 llm-client.mjs 注释里）。
3. **wrap 软合并 PM 决策待办**：Agent 7 推荐 N=80，但需要 PM 拍板要不要加；现在 pin 行为。
4. **真实 LLM 5 篇抽样失败原因明确化**：拆 A-side / B-side 后，问题清楚是 B-side（provider 端不响应 disabled 指令）。这是 round-9 的 P0。

## 失败/坑

- **B-side thinking block 静默忽略**：`thinking: { type: "disabled" }` 在请求体里出现，但 MiniMax M2.7 不消费、不报错、依然发 thinking block。Anthropic API spec 写了 supported，但实际 MiniMax M2.7 没实现。
- **错误消息不向后兼容**：round-8 改 `extractAnthropicText` 抛错信息从 "did not include text content" → "MiniMax response contained only thinking blocks (1) (stop_reason: max_tokens); no text block was emitted."。`isStructuredOutputError` 没同步更新，导致 retry 不触发，test 7 fail。已同步加 `contained only thinking blocks` 到正则。
- **`parsePromptParagraphs` helper 误抓 few-shot**：新 prompt 格式 `Paragraph 0: text` 在 few-shot 块和"now produce"块都出现，旧 helper 只看 `indexOf("Paragraphs:")` 抓 JSON，新 helper 需先按 footer 切分再 match 段落行。
- **3 个 `llm-client.test.mjs` 旧测试失败**（tests 6, 7, 8）：helper 不匹配 + clip OOB 后断言变化。已修：helper 重写为按 footer 切分后 match；test 8（"rejects invalid"）改名为"clips out-of-bounds spans"，因为代码已 clip 不 reject。
- **5 篇真实 MiniMax 抽样 3/5 失败**：1 个成功 retry（拆 batch 后正常），2 个 retry 链全空。**与 B-side 失败同源**。

## 产品层发现

- **真实 LLM 失败率曝光**：用户要求诚实写文档，README 明确写 ~50% 空响应率。B-side 修是 round-9 P0 候选路径（system-prompt 显式禁用 + max_tokens 调高 + 换 model）。
- **测试断言要跟代码走**：clip OOB 后断言从 reject 改为 "drop + still minimax provider"，这反映了代码设计意图（"永不静默伪装成 mock"）。新测试是"代码契约"，不是历史断言。
- **Agent 7 wrap 决策研究是独立产物**：162 行研究报告，PM 可以独立 review。`/compare` 页面不受影响（pin 行为保持）。
