## 关键决策

1. **保留 v2 splitMode auto** —— 覆盖真产品风险（飞书/Notion 单 `\n` 粘贴），向后兼容，8/8 测试 + 6 case + 50 篇综合全过。
2. **保留英文 Rule 8 17-25%** —— Agent B 物理校准，2-char span 在英文 4-8 字符单词上做不到 35-50%，强行 35-50% 会重新触发 round-6 的 digraph bug。
3. **LLM-as-judge 不可信** —— Agent D 验证发现 judge 评分与 deterministic check 反向相关（judge 不知 2-char saccade 设计，把规则合规的输出判低分）。Wave 3 用 deterministic + 人工 spot-check。
4. **wrap 误切 pin 行为** —— Agent A 故意 pin（"一段被 wrap 成多行"→ 切成多段）。未来如果客户实测反馈高频问题，再加"软合并"启发式；现在 pin 即可。
5. **英文 few-shot 选 5 条** —— pangram / Chekhov / Dickens / Austen / Tolkien，覆盖短/中/长、重复 content word、function cluster、抽象名词、描述性小说。Agent B 多样性决策详细写在 `REPORT.md §1`。

## 失败/坑

- **thinking 模式偶发空响应**：5 篇真实 MiniMax 抽样里 2 篇 (ZH-21 多段 / EN-07 长单段) 返回 `content: []` 或 `[{type: 'thinking'}]` 无 text block。`isStructuredOutputError` 触发 retry，但单段 retry 仍空。**与 Wave 1 改动无关**，round-6b 已观察到。
  - **建议**：`extractAnthropicText` 显式 skip `type: 'thinking'` block，或在 system message 加 `disable thinking`。
- **Rule 3 dead for English**：英文段开头是 function words 时（"It was the best..."），模型先 skip function word 优先级高于"first 2-3 chars anchor"，导致首 anchor 跳到位置 11。Agent B 写 few-shot 时已经在 pangram 里强制锚 "Th"（"The"）来骗 Rule 3，但模型学会的是"skip function word"才是对的。**建议改 Rule 3 措辞为 "first content word"**。
- **en-12 density 抖动**：162 chars / 12 spans 一次跑 14.7%（低于 15% floor），多次重测 14.7-18.4% 区间。模型非确定性导致。Wave 3 应保留 ±2pp 容差。
- **3 个 `llm-client.test.mjs` 旧测试失败**（tests 6, 7, 8）：Agent B 报告"out of scope"，原因是测试 helper 期望 `Paragraphs:` 字面量，prompt 里没有。本次不修。
- **2-wave agent-swarm 一次跑 5 agents 总 wall-clock 50 min**：与 round-6 4 agents 跑 1.5h 比，加速 ~2x。**结论：2-wave 模式 + 严格文件边界 = 高效**，值得固化到 skill 库。

## 产品层发现（重要）

- **英文路径已可用**：digraph bug 修好，12 篇 11/12 deterministic pass。**这意味着 web-mvp 之前只对中文有效的限制解除**，可以声称"任何文章"（中文 + 英文 + 大概率其他拉丁字母语言）。这是产品定位的关键升级。
- **2-wave agent swarm 模式 2 轮验证有效**：round-6 跑过 1 次（4 agents），round-7 跑过 1 次（5 agents），都 0 冲突、0 误报。已写进 memory。
- **wrap 误切是真产品问题**：editor 自动换行的长段被切碎，5 行散文/技术文体验上不如 1 段连贯。是 round-6 PM 反馈 + Agent B 多段测试踩的同一个坑，需要产品决策（软合并 vs 当前 pin）。
